# Chrome GUI Pilot — agent notes

- Working notes between sessions live in `docs/handoff/NN_项目交接文档_*.md` (index: `docs/handoff/README.md`). They are local only — git-ignored, absent from a fresh clone, and must not be pushed. When they exist, read the newest one first; links inside are relative to `docs/handoff/` (`../../scripts/...`).
- Full regression: `.\.venv\Scripts\python.exe -u .\scripts\test_cua_mcp.py` (launches isolated Chrome + llama-server, ~2 min, overwrites `artifacts/cua_ui_preview`).
- UI-only preview: `python -c "import sys;sys.path.insert(0,'scripts');import test_cua_mcp as t;t.test_ui_preview()"`.
- Floating panel = `scripts/chrome_pilot_panel.py` (Tkinter + PIL supersampled art). Never name Canvas attributes `self._w` — it shadows Tk's widget path and crashes.
- Git: public repo `https://github.com/Assangejulian/chrome-cua-mcp` (branch `main`). `artifacts/`, `models/`, `tools/`, `profiles/` (managed-Chrome login state) are git-ignored and must stay that way. Never commit the owner's email, Google Drive IDs, or links that identify their accounts (the local handoff docs contain them). Do not set git config; do not push unless asked. The public `README.md` must only link to tracked files and only state things verified against the code or measured.
- Panel (v16): smoked-glass dark bar. Material = `apply_glass_material()` (acrylic accent policy on a PURE BLACK Tk window: GDI black composites as blurred glass, every other pixel is ADDED on top, hit-testing intact; `CHROME_PILOT_GLASS=0` → opaque fallback). So: backgrounds must be exactly `GLASS` (#000000), use light ink and light fills, never a colour key. PrintWindow cannot see the glass — previews must be real screen grabs (`_grab_panel` in tests, `artifacts/backup_20261121_v16/preview_panel.py`). At rest ONE line (seal · command · 执行); then on demand: one status line, the confirmation block (only when an action is actually stopped), one settings line of self-naming `Dropdown`s + icon switches — order enforced by `_relayout()`. No standing technical info (endpoint lives in the connect menu), no row labels, no confirmation chatter; extra detail goes in a `Tooltip`. Real-pointer check `hover_probe.py`, live MCP check `live_mcp_probe.py` (same folder).
- Panel motion (v17): every animation is a `Tween` (time-based, ease-out, replaces itself when re-run; `CHROME_PILOT_MOTION=0` or `cpp.MOTION_SCALE = 0.0` lands everything instantly — `test_ui_interactions` runs that way, `test_ui_motion` checks the animated path). Rules: content is live from frame one (never gate a click or the risk confirmation on an animation), keep durations ≤ ~220 ms, animate colour/height/opacity only. On-demand content lives in `self.tray` (unpacked when shut — a Tk frame cannot request height 0). `-alpha` 1.0 on a glass window composites identically to no alpha, so fades are safe. Slow-motion evidence: `artifacts/backup_20261121_v17/motion_filmstrip.py`.
- Tk gotchas: calling `root.after` from another thread only works under `mainloop()` (a `root.update()` loop makes each call wait 1 s and fail); `_ART_CACHE` PhotoImages die with their Tk root, so a second panel in one process must clear it (done in `_setup_window`).
- MCP payloads default to `detail="brief"` (`cua_observe`, `cua_navigate`, `cua_run_steps`); pass `detail="full"` when a script needs `trace[i]["input"]`, `raw_prediction`, `dom_signature`, `frame_size`. Engine Python methods `observe()`/`navigate()` still default to full.
- Never drop or rename `status` / `submitted` / `submission_*` / `require_submit` in brief traces; `test_v14_efficiency_contracts` guards this.
- Local VLM prewarm is OFF by default (user decision, 2026-11-21): the model loads lazily on the first visual call. Opt in with `CUA_PREWARM=1` (also `true`/`on`/`yes`) to load it on the first non-status MCP tool call or panel submit; the test suite forces `0`. Close engines with `engine.close()` so `grounder.shutdown()` cancels an in-flight load.
- Perf evidence scripts: `scripts/profile_python_overhead.py --out <json>`, `scripts/benchmark_llama_flags.py --out <json>` (run configs in both orders; the first config in a session measures slower).
- Shell heredocs above ~8 KB get truncated by the agent shell; write big files with the file tool.
- `ChromePilotPanel()` binds to an already-open desktop Chrome at startup (`target_mode="desktop"`, real keyboard/mouse into the user's own browser). Any script that drives a panel or its engine must call `panel._set_target_mode("managed")` first and check `engine.target_mode == "managed"` before every action — `scripts/record_demo.py` (`managed_only`) shows the pattern. A dry run without this once navigated the user's real tab.
- README demo: `scripts/record_demo.py` → `assets/demo.gif` (real panel + HTTP MCP + local model on a local page in an isolated Chrome; captures only that window). Tk drops a pending `root.geometry("+x+y")` if `-topmost`/`lift()` follow in the same callback — call `update_idletasks()` in between.
